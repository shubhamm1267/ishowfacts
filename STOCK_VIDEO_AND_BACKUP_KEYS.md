## Optional YouTube Creative Commons excerpts

Request pacing now serializes YouTube subprocesses across jobs, leaves five seconds between completed requests, and asks yt-dlp to wait one second between internal requests and five seconds before a download. Transient extraction/time-out failures retry once; authentication/rate-limit blocks do not retry and open a two-minute process-wide cooldown. The existing per-job circuit also skips later scene requests after a block. These limits reduce repeated requests but cannot guarantee access from a deployment IP. A later local diagnostic downloaded a 4.1-second CC-licensed excerpt without cookies; that 720p synthetic clip was only an access test, not eligible production footage.

`ENABLE_YOUTUBE_CC=1` enables a CC-filtered YouTube web search before existing stock sources. It does not use the YouTube Data API. `yt-dlp[default]` and FFmpeg are included in the deployment dependencies; Node supplies its JavaScript runtime. Local installation uses the same Python interpreter configured by `PYTHON`.

Each candidate must explicitly declare `Creative Commons Attribution license (reuse allowed)` in extracted metadata. Standard, unknown, private, live, age-restricted and low-resolution candidates are skipped. Descriptions saying “no copyright” are insufficient. Candidate download repeats the licence filter, requests only a bounded 4–15 second section, and enforces time and disk limits. Chapters matching the scene query guide the excerpt when available; otherwise the existing three-frame Gemini subject/crop review decides whether it is usable. A chapter/title match alone is not proof of relevant footage.

Accepted excerpts preserve the creator, title, source URL, CC BY licence, excerpt timestamps and modification notice in `CREDITS.json`, with attribution in the rendered shot. Original audio is discarded. The regular job/cache retention policies apply. One blocked request disables this provider for the rest of that job and licensed stock/photo fallback continues. `stock-performance.json` records searches, downloaded/accepted excerpts and a sanitized unavailability reason.

CC BY is a content-reuse licence, not YouTube platform permission to download. YouTube API clients have additional download restrictions; this adapter does not obtain permission from YouTube or guarantee legal clearance of an uploader's material. See [YouTube licences](https://support.google.com/youtube/answer/2797468), [YouTube terms](https://www.youtube.com/t/terms) and [yt-dlp section downloads](https://github.com/yt-dlp/yt-dlp#usage-and-options).

Consequently no YouTube footage was verified or downloaded in that check. Provider tests exercise licence rejection, bounded excerpts, attribution, frame-review rejection and the per-job block circuit; they do not prove live YouTube access from Render.

`studio/.env` now contains the supplied Gemini backup keys as `GEMINI_API_KEY_2` and `GEMINI_API_KEY_3`, and Vecteezy credentials as `VECTEEZY_ACCOUNT_ID` / `VECTEEZY_API_KEY`. The primary key remains unchanged. Actual secrets are only in the ignored `.env`; `.env.example` has empty placeholders.

Gemini requests try the primary first, then backup 2, then backup 3 when earlier credentials encounter invalid/expired keys, authentication/permission errors, quota/rate limiting, network timeouts or server failures. A successful primary never calls the backups. Invalid request/model errors stop immediately. If every configured key fails, the job reports a sanitized error. Keys in the same Google project may share quota; backups cannot remove project limits. All three supplied keys returned HTTP 200 in a small live check.

The reference UI now prefers real clips for EVERY shot: up to 30 seconds uses five shots, 31-40 uses seven, and 41-50 uses nine. There is no fixed photo quota. Each shot tries relevant video candidates first and can use a verified licensed photo if footage is unavailable. Missing media receives a bounded alternate-query retry. Jobs still stop if neither type passes the existing topic, crop, resolution and license checks. The original paper layout retains its explicit photos-only option. Shot timing still follows measured narration; these counts do not guarantee exact requested duration.

Vecteezy uses its official v2 search, metadata and licensed-download endpoints. The adapter requests commercial, non-AI video results, verifies the item page is a **Free Video**, and accepts bounded-size MP4 originals only. It does not download paid resources or watermarked preview files. Vecteezy attribution is burned into the displayed clip and saved in `CREDITS.json`. See the [API documentation](https://www.vecteezy.com/api-docs/index.html) and [Free License conditions](https://www.vecteezy.com/licensing-agreement).

Mixkit uses a small on-demand category search and checks up to three item pages per search. Only items explicitly declaring the **Stock Video Free License** at the actual download link are accepted. Restricted/personal-use items are rejected, even when their JSON-LD incorrectly links to `videoFree`. There is no bulk downloader. Many current results are Restricted and will be skipped. See [Mixkit licenses](https://mixkit.co/license/) and [terms](https://mixkit.co/terms/).

These are licensed stock resources, not public-domain/copyright-free assets. Vecteezy Free requires attribution and imposes project-use limits; a Free label alone does not grant unlimited rights. Credits preserve each source and license URL.

Before a clip enters a job, FFmpeg extracts silent frames for the measured narration duration. Gemini inspects three points in the sequence for the actual subject and narrated context, with a strict confidence threshold of 0.85 in reference mode. This runs even if still-image QA is disabled. Failed inspection tries another licensed candidate. Required reference clips remain clips; an unresolved missing asset fails the job. The Python renderer reads successive frames at video FPS, preserves the full image aspect ratio, and retains existing scene overlays, titles, narration and SFX. Original clip audio is excluded.

Settings: `ENABLE_STOCK_VIDEO=0` disables footage; `STOCK_VIDEO_MAX_SCENES=3` caps legacy paper shots (reference mode uses its duration budget); `STOCK_VIDEO_MAX_MB=80` caps each downloaded clip (hard maximum 120 MB). Source downloads and extracted frames live in the existing job assets directory and follow the 30-minute completed-job retention policy.
